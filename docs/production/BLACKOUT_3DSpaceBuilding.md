# BLACKOUT — Unity에서 3D 공간을 쉽게 구성하는 법

> 대상: Unity 6 URP · 모듈형 환경 에셋 · BLACKOUT 화물역  
> 목표: 예쁜 장면을 먼저 만드는 것이 아니라, 플레이할 수 있는 공간을 빠르게 만들고 검증한다.

## 1. 왜 바로 소품부터 배치하면 어려워질까

3D 공간은 벽·바닥·소품을 많이 놓는다고 게임 맵이 되지 않는다. 플레이어가 걷고, 카메라가 따라가고, 적과 싸우며, 목표까지 도달할 수 있어야 한다. 처음부터 조명과 장식까지 만들면 나중에 길을 바꿀 때 전부 다시 옮겨야 한다.

따라서 공간은 아래 순서로 만든다.

```text
이동 경로 → 전투 공간 → 게임 규칙 배치 → 조명 → 장식
```

이 문서의 예시는 `SciFi Warehouse Kit`을 이용한 화물역 구간이다. 에셋의 Demo 씬은 참고만 하고, 게임 맵은 새 씬에서 만든다.

## 2. 이번에 적용할 범위

| 지금 적용 | 이유 |
|---|---|
| 새 `CargoStation` 씬 | 실제 게임 맵을 Demo 씬과 분리한다. |
| 모듈형 바닥·벽·기둥 | 빠르게 길과 방의 크기를 바꿀 수 있다. |
| 1개 Directional Light | 그림자 문제를 피하며 구조를 확인한다. |
| 플레이어 크기 기준 | 문·통로·엄폐물의 실제 사용성을 확인한다. |
| 짧은 시작 구역→첫 전력 시설 | W02~W03에 검증할 수 있는 작은 목표다. |

| 나중에 적용 | 지금 미루는 이유 |
|---|---|
| 전체 화물역 장식 | 길과 전투 규칙이 아직 바뀔 수 있다. |
| 복잡한 라이트 베이크 | 모듈과 조명 배치가 확정된 뒤 한 번만 한다. |
| 보스 경기장 완성 | 기본 이동·전투가 검증된 뒤 만든다. |
| Occlusion Culling, LOD 세부 조정 | 실제 성능 문제가 확인된 뒤 적용한다. |

## 3. 씬과 폴더

```text
Assets/BLACKOUT/
├─ Scenes/
│  ├─ Sandbox/
│  │  └─ EnvironmentKitTest.unity
│  └─ Levels/
│     └─ CargoStation.unity
└─ Prefabs/
   └─ Environment/
```

- `EnvironmentKitTest`: 에셋의 크기, 재질, Collider, 모듈 연결을 시험하는 장소다.
- `CargoStation`: 실제 플레이 경로를 만드는 게임 씬이다.
- `Prefabs/Environment`: 여러 씬에서 다시 쓸 수 있게 조합한 우리 게임용 구조물이다.

에셋 원본은 `Assets/ThirdParty/SciFi Warehouse Kit`에 둔다. 원본 Prefab을 직접 고치기보다, 필요한 모듈을 조합한 새 Prefab을 `BLACKOUT` 아래에 만든다.

## 4. 시작 전 5분 점검

### 4-1. 분홍색 프리뷰를 먼저 해결한다

분홍색은 텍스처가 없다는 뜻이 아니라 셰이더가 현재 렌더 파이프라인과 맞지 않는다는 뜻이다. 이 에셋은 오래된 Built-in 재질이므로 URP 재질로 변환한 뒤 사용한다.

1. `Assets/ThirdParty/SciFi Warehouse Kit/Art/Materials`를 연다.
2. 일반 재질을 선택한다.
3. `Edit > Rendering > Materials > Convert Selected Built-in Materials to URP`를 실행한다.
4. 바닥 Prefab의 프리뷰가 분홍색이 아닌지 확인한다.

`Dune Skybox.mat`처럼 하늘 전용 재질은 일반 구조물 재질과 분리해 나중에 확인한다.

### 4-2. 데모 조명은 가져오지 않는다

Demo 씬에는 수십~수백 개의 Point/Spot Light가 있을 수 있다. 초기에 이를 그대로 사용하면 그림자 해상도 경고와 프레임 저하가 생긴다.

처음에는 다음만 사용한다.

```text
Directional Light 1개: 그림자 켬
Point / Spot Light: 필요한 곳에만, 그림자 끔
```

## 5. 모듈형 공간을 만드는 핵심: 격자와 기준점

모듈형 에셋은 레고처럼 정확한 크기로 이어 붙이도록 만든 부품이다. 부품을 임의 위치에 놓으면 벽 사이에 틈이 생기고, Collider도 어긋난다.

### 5-1. 이동 도구

- `W`: 이동 도구
- `E`: 회전 도구
- `R`: 크기 조절 도구
- `V`를 누른 채 이동: 꼭짓점 기준 스냅
- `Ctrl`을 누른 채 이동: 격자 단위 스냅
- `Ctrl`을 누른 채 회전: 일정 각도 회전

처음에는 바닥 타일 하나를 배치하고 Inspector의 `Transform > Scale`을 보지 말고, 원본 크기를 유지한다. 크기를 임의로 늘리기보다 같은 타일을 반복 배치한다.

### 5-2. 기준 크기 정하기

에셋의 바닥 타일 하나가 몇 m인지 확인한 뒤, 그 크기를 맵의 기본 단위로 사용한다. 예를 들어 바닥 하나가 4m라면 통로 폭도 `4m`, `8m`, `12m`처럼 정수 배수로 만든다.

```text
바닥 1칸 = 공간의 단위
통로 폭 = 1~2칸
작은 전투 공간 = 3×3칸
보스 공간 = 6×6칸 이상
```

정확한 숫자보다 모든 구조가 같은 단위를 공유하는 것이 중요하다.

## 6. 실제 공간 제작 순서

## 6-1. 1단계 — 이동 가능한 바닥 만들기

### 목표

플레이어가 시작 지점에서 첫 목표 지점까지 막힘 없이 걸어간다.

1. `CargoStation` 씬을 만든다.
2. 바닥 타일만으로 직선 경로를 8~12칸 만든다.
3. 시작점에는 빈 GameObject `PlayerSpawn`을 둔다.
4. 끝에는 빈 GameObject `PowerStation_01`을 둔다.
5. 플레이어를 배치해 실제로 끝까지 걸어 본다.

이 단계에서는 벽, 상자, 조명 장식이 없어도 된다.

### 완료 기준

- 플레이어가 바닥 아래로 빠지지 않는다.
- 카메라가 바닥이나 벽을 뚫지 않는다.
- 시작점에서 목표점까지 길이 명확하다.

## 6-2. 2단계 — 벽과 천장으로 경계 만들기

이제 바닥의 양옆에 벽을 붙인다. 통로 전체를 막는 벽보다, 플레이어가 다음 공간을 궁금해할 수 있게 일부가 보이는 구조가 좋다.

```text
나쁜 예: 긴 직선 복도만 계속된다.
좋은 예: 직선 구간 → 꺾이는 구간 → 작은 열린 공간
```

벽을 배치한 뒤에는 항상 Play Mode에서 점프와 카메라 회전을 확인한다. Scene View에서 보기 좋은 간격이 실제 TPS 카메라에는 너무 좁을 수 있다.

## 6-3. 3단계 — 전투 공간을 먼저 비운다

적과 싸울 구역은 소품을 놓기 전에 빈 바닥으로 크기부터 확인한다.

| 공간 | 시작 권장 크기 | 확인할 점 |
|---|---:|---|
| 통로 조우 | 바닥 1~2칸 폭 | 적을 피하거나 옆으로 지나갈 수 있는가 |
| 일반 전투 | 바닥 3×3칸 | 이동·조준·회피가 가능한가 |
| 보스전 | 바닥 6×6칸 이상 | 카메라가 물러날 자리와 좌우 회피 폭이 있는가 |

공간이 너무 좁으면 적이 강해 보이는 것이 아니라 카메라가 답답해 보인다.

## 6-4. 4단계 — 게임 규칙을 보이는 물체로 배치한다

BLACKOUT에서는 공간 장식보다 전력 시설이 먼저다.

1. `PowerStation_01` 위치에 전력 소켓 또는 패널을 둔다.
2. 전력이 들어가면 열릴 길에는 승강기, 문, 조명을 둔다.
3. 전력이 들어가면 위험해지는 위치에는 포탑 또는 적 Spawn 위치를 둔다.
4. 플레이어가 시설을 보기 전에 적에게 공격받지 않도록 시야와 거리부터 확인한다.

```mermaid
flowchart LR
    A[시작 지점] --> B[작은 조우]
    B --> C[전력 시설]
    C --> D[조명 또는 길 활성화]
    D --> E[다음 전투 공간]
```

## 6-5. 5단계 — 소품은 길을 설명할 때만 놓는다

상자, 팔레트, 케이블, 난간은 빈 공간을 채우기 위한 장식이 아니다. 각각 다음 중 하나의 역할이 있어야 한다.

| 역할 | 예시 |
|---|---|
| 길 안내 | 난간, 바닥선, 조명 |
| 엄폐 | 화물 상자, 기둥 |
| 위험 예고 | 끊어진 케이블, 경고등, 파손 난간 |
| 공간 이야기 | 적재 팔레트, 정비 카트, 출입 표지 |

역할 없는 소품은 나중에 추가한다. 특히 플레이어 발밑과 카메라 뒤쪽에는 작은 소품을 많이 놓지 않는다.

## 7. Hierarchy를 읽기 쉽게 유지하는 법

씬 안의 오브젝트를 역할별 부모 GameObject로 묶는다.

```text
CargoStation
├─ Environment
│  ├─ Architecture
│  ├─ Props
│  └─ Collision
├─ Gameplay
│  ├─ PlayerSpawn
│  ├─ EnemySpawns
│  ├─ PowerFacilities
│  └─ Checkpoints
├─ Lighting
├─ Navigation
└─ Debug
```

`Floor Tile 01 (23)`처럼 자동 이름을 그대로 두지 않는다. 반복 모듈은 부모 아래에 두고, 의미 있는 덩어리에는 `StartCorridor`, `FirstEncounter`, `PowerRoom`처럼 구역 이름을 붙인다.

## 8. 조명은 마지막이 아니라 단계적으로 한다

### 구조 확인 조명

맵의 크기와 충돌을 확인할 때는 Directional Light 하나만 둔다.

### 게임 정보 조명

전력 소켓, 진행 방향, 위험 경고에만 작은 Point/Spot Light 또는 Emission을 쓴다. 대부분의 추가 조명은 그림자를 끈다.

### 분위기 조명

경로와 전투가 확정된 뒤에만 어두운 구역, 비상등, 반사광을 추가한다.

정전 상태를 만들 때도 화면 전체를 검게 만들지 않는다. 플레이어가 이동할 길, 위험물, 상호작용 지점은 항상 구분되어야 한다.

## 9. 매 단계에서 Play Mode로 확인할 질문

1. 플레이어가 바닥 아래로 떨어지지 않는가?
2. 카메라가 벽을 뚫거나 너무 가까워지지 않는가?
3. 다음 목표가 눈에 들어오는가?
4. 소품이 이동과 조준을 방해하지 않는가?
5. 전력 시설과 위험 요소의 관계가 이해되는가?
6. Console에 빨간 오류가 없는가?

하나라도 아니면 장식을 더하지 말고 해당 구조부터 고친다.

## 10. 첫 번째 미니 목표

### 만들 것

`CargoStation` 안에 1~2분 동안 걸어볼 수 있는 아래 구간을 만든다.

```text
PlayerSpawn
  → 짧은 통로
  → 작은 상자 엄폐 구역
  → PowerStation_01
  → 켜지면 보이는 다음 문 또는 승강기
```

### 완료 기준

- 바닥·벽·기둥이 격자에 맞게 이어진다.
- 바닥과 벽의 재질이 분홍색이 아니다.
- 플레이어와 TPS 카메라가 구간을 정상 통과한다.
- Directional Light 1개와 필요한 최소 조명만 있다.
- Console에 스크립트 중복 또는 셰이더 관련 빨간 오류가 없다.

## 11. 자주 생기는 문제

| 증상 | 원인 | 먼저 할 일 |
|---|---|---|
| Prefab이 분홍색 | Built-in 재질과 URP가 맞지 않음 | 재질을 선택 변환한다. |
| 조명 그림자가 거칠거나 경고가 반복됨 | Point/Spot Light가 너무 많음 | 추가 조명 그림자를 끄고 수를 줄인다. |
| 벽에 틈이 생김 | 격자 단위가 맞지 않음 | Scale을 원래대로 하고 스냅으로 다시 배치한다. |
| 플레이어가 걸림 | Collider 또는 작은 소품이 길을 막음 | Collider를 확인하고 장식 소품을 옮긴다. |
| 씬이 복잡해 찾기 어려움 | Hierarchy에 역할 구분이 없음 | Environment, Gameplay, Lighting 부모를 만든다. |

## 12. 다음 단계

첫 구간이 완성되면 그 공간에 W03의 펄스 발사체와 표적을 넣는다. 공간은 다시 만들지 않고, 이미 만든 통로와 작은 전투 구역에서 발사체 충돌·명중 표시를 검증한다.
