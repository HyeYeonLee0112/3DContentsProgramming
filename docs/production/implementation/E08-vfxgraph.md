# E08 — 전력 입자를 Particle System과 VFX Graph로 비교하기

흡수 연출에 많은 입자를 쓰고 싶을 때 GPU 기반 효과가 항상 더 나은지 직접 확인한다. 같은 화면·밀도·시간으로 비교한다.

선행: [T11](11-feedback-pool.md), [T26](26-profiler-validation.md) · 로드맵 X06

## 책임·작업 계약

| 대상 | 실험 계약 |
|---|---|
| 기존 Particle System 프리팹 | 비교 기준; 입력·수명은 흡수 시작/취소/완료 |
| VFX Graph 프리팹 | 같은 출발점·도착점·효과 시간·색 |
| 표시 연결 | Absorb의 진행 상태를 읽어 시작·중단; 전력 지급 함수를 호출하지 않음 |
| 추가 공개 속성 | `SourcePosition`, `TargetPosition`, `Progress` 이름·형식을 Graph와 호출부에서 일치 |

VFX Graph 패키지와 URP·플랫폼 지원을 설치 때 확인한다. 본편의 Particle System을 먼저 삭제하지 않는다.

## 질문·의사코드

입자가 화면을 꽉 덮으면 GPU 시뮬레이션이 빨라도 투명 픽셀 비용이 커질 수 있는가?

```text
같은 목표 효과 → 두 구현 → 고정 밀도·카메라·시간
정상 흡수/취소/재사용 → CPU·GPU·메모리·가독성 비교
```

## 따라하기

1. 실험 장면에서 기존 흡수 효과의 입자 수·화면 크기·지속 시간을 기록한다.
2. VFX Graph의 Spawn→Initialize→Update→Output 단계로 같은 이동을 만든다. 처음에는 적은 수로 확인한다.
3. Source/Target 속성을 실제 Transform 위치에 연결한다. 비활성·취소 때 Spawn이 멈추고 남은 입자를 지울지 자연 종료할지 정한다.
4. 두 효과를 동시에 켜서 비교하지 않고 하나씩 같은 경로에서 측정한다.
5. 적은 수/많은 수, 화면 근접, 반복 흡수 20회에서 GPU·CPU·메모리와 visual noise를 관찰한다.
6. 풀로 재사용할 때 이전 이벤트·입자·좌표가 남는지 확인한다. 기능 시작/취소가 일치하는 경우에만 본편 통합을 판단한다.

## TODO·완료 기준

입자 수를 먼저 높이지 말고 “취소하면 언제 어떤 입자가 사라지는가”부터 기록한다. 수명 규칙은 두 구현에서 같아야 한다.

- [ ] 같은 목표 효과와 취소 정책으로 비교했다.
- [ ] 반복 재사용 후 과거 입자·좌표가 남지 않는다.
- [ ] CPU/GPU/메모리와 화면 가독성 수치를 기록했다.
- [ ] 실제 규모에서의 채택 또는 보류 이유가 있다.

VFX Graph는 많은 시각 입자를 다루는 선택지이며 작은 효과에는 제작·버전 관리 비용이 더 클 수 있다.
