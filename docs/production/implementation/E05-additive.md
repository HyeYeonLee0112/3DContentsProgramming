# E05 — 방 두 개를 Additive 장면으로 나누기

여러 사람이 구역을 제작하거나 필요한 방만 불러오려면 장면을 나눌 수 있다. 단순 로드가 아니라 준비 완료·중복 객체·언로드 후 참조까지 검사한다.

선행: [E04](E04-addressables.md) · 로드맵 X03 · [전체 목록](README.md)

## 책임·작업 계약

| 대상 | 필요한 역할 |
|---|---|
| LabBootstrap 장면 | 플레이어·GameFlow·UI·AudioListener의 유일한 주인 |
| RoomA/RoomB 장면 | 환경·시설·로컬 적만 포함 |
| `Experiments/AdditiveRoomLab.cs` | `public void LoadRoom(string sceneName)`; `public void UnloadRoom(string sceneName)`; 진행 중 요청과 로드 완료 상태 보관 |
| 연결 단계 | 로드 완료 → 구역 ID 검사 → 외부 참조 전달 → 준비 완료 → 행동 허용 |

첫 버전은 SceneManager.LoadSceneAsync와 UnloadSceneAsync로 로컬 장면만 사용한다. Addressables 장면 로드는 핸들 정책까지 추가되므로 기본 성공 뒤 별도 비교한다.

## 먼저 생각하기·의사코드

장면 로드가 끝났다는 것과 구역의 적이 플레이어 참조를 받았다는 것은 같은가? 언로드된 시설을 UI가 계속 구독하면 어떻게 되는가?

```text
중복 요청 검사 → Additive 로드 → 로컬 객체 준비·연결
준비 완료 뒤 전투 허용 → 구역 종료 때 작업 취소·구독 해제 → 언로드
```

## 따라하기

1. 기존 본편을 즉시 분리하지 않고 대역 방 두 개와 Bootstrap을 만든다.
2. 방에는 플레이어·AudioListener·EventSystem을 복제하지 않는다. 조명 환경·활성 장면 설정의 영향을 확인한다.
3. LoadRoom을 연결하고 로드 중 같은 버튼을 다시 누른 경우의 정책을 정한다. 처음에는 진행 중 요청을 거절한다.
4. 준비 완료 전에는 지역 AI를 멈추고 명시적 Initialize로 플레이어·흐름을 연결한다. 장면 전역 Find 순서에 기대지 않는다.
5. 언로드 전에 흡수·공격·UI 구독을 취소한다. 다른 방의 코드가 사라진 Facility 참조를 잡고 있지 않은지 확인한다.
6. A/B 이동 10회, 없는 장면·중복 로드·로딩 중 이탈·이전 구역 흡수 중 언로드를 시험한다.

## 완료 기준

- [ ] 카메라·플레이어·UI·AudioListener가 중복되지 않는다.
- [ ] 로드와 게임 준비 완료를 구분한다.
- [ ] 반복 출입·언로드 후 과거 구독/공격이 없다.
- [ ] 메모리·조명·참조 관리 비용을 기록했다.

Additive는 구역 제작·로딩을 나누지만 초기화·전역 상태·조명 관리가 늘어난다. 한 장면 BLACKOUT의 필수 복원 범위를 자동으로 여러 장면 저장으로 확장하지 않는다.
