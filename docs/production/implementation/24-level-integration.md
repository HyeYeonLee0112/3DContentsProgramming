# T24 — 화물역 진입부터 보스 승리까지 연결하기

각 기능이 Sandbox에서만 동작하면 게임 한 판이 되지 않는다. 이동·전투·전력 선택을 같은 장면에서 순서대로 경험하게 만들고 막히는 경우를 검사한다.

선행: [T23](23-boss.md) · 다음: [T25](25-settings.md), [T26](26-profiler-validation.md)

## 파일 책임과 작업 계약

| 대상 | 이번 작업 | 소유·책임 |
|---|---|---|
| `Scenes/Levels/`의 본편 장면 | 실제 파일을 확인하고 작업 복사본에서 통합 | 환경·적·시설 배치 |
| 기존 Player/AI/Facility/Checkpoint 프리팹 | 검증된 버전으로 연결 | 각 기능의 상태 |
| ObjectivePresenter·GameFlow | 목표 전환·승리 연결 확장 | 진행 안내와 행동 허용 |
| 에셋 원장·레벨 검수 기록 | 사용 경로·검증 상태 갱신 | 실제 근거만 기록 |

새 범용 LevelManager 코드를 자동 추가하지 않는다. 기존 책임으로 부족한 구체적 진행 조건이 생기면 그 조건만 작은 컴포넌트로 분리하고 멤버 계약을 적는다.

## 먼저 생각하기

플레이어가 전력을 엉뚱한 시설에 두고 왔을 때 회수할 길이 남는가? 모든 적이 죽었고 전력은 꽉 찼는데 필수 문을 열 수 없는 경우가 있는가?

```text
진입 → 첫 소켓 발견 → 추적 로봇 → 잔류 흡수
문+포탑 선택 → 승강기 2칸 → 체크포인트·충전소 → 보스 → 송전 복구
각 구간에서 필요한 전력과 되돌아갈 길 검증
```

## 따라하기·Unity 연결

1. PRD의 5구간을 한 장면 지도에 표시한다. 전체 5개 대규모 구역을 추가 구현하는 의미가 아니라 제출 기준의 연결 구간이다.
2. 첫 2분은 이동·조준·꺼진 시설의 필요를 공간에서 보여준다. 텍스트를 읽지 않아도 소켓·불빛·위험을 구분하는지 본다.
3. 회로별 전력 용량과 생성/소비/보관 위치를 표로 작성한다. 시설의 전력을 회수할 수 있어 자원이 갇히지 않는지 검사한다.
4. 문·승강기·보스 진입을 순서대로 연결한다. 본편에만 있는 Collider·조명·NavMesh·카메라 모서리 문제를 다시 검사한다.
5. 보스 진입 전 안전 위치에 자동 체크포인트를 둔다. 이동 경로와 탄환 Spawn이 복원 지점을 막지 않는지 확인한다.
6. 실제 에셋의 스케일·Pivot·URP Material·Collider·Rig·모듈 결합·프레임 비용을 확인한다. 설치됐다는 사실과 제작용 승인을 구분한다.
7. 처음 하는 사람의 플레이를 관찰한다. 막힌 위치·헷갈린 안내·사망 원인을 기록하고 플레이 시간을 잰다. 조작법을 먼저 설명해 주어 테스트를 왜곡하지 않는다.

## 실패 경로 표

| 일부러 할 행동 | 통과 조건 |
|---|---|
| 모든 전력을 작업등에 넣고 돌아오기 | 필수 진행에 필요한 전력을 다시 회수 가능 |
| 승강기 위층에서 죽기 | 하단의 안전한 저장 상태로 복원 |
| 적을 다른 구역까지 유인 | 조우·길찾기·회수 가능한 보상 정책이 일관됨 |
| 보스전 직전 충전소 사용 | 선택과 Snapshot 시점에 맞는 사용 상태 유지 |
| 문 앞에서 연속 주입·회수 | 끼임·복제·잘못된 포탑 상태 없음 |

## 완료 기준

- [ ] 진입부터 승리까지 같은 장면에서 중단 없이 진행한다.
- [ ] 전력 배치 실수 후 회수 경로가 있어 진행 불능이 없다.
- [ ] 처음 하는 사람이 목표·위험·실패 이유를 파악한다.
- [ ] 10~15분 제출 구간의 실제 플레이 시간과 차이를 기록했다.
- [ ] 전체 플레이 영상 또는 빌드를 증거로 남겼다.

## 선택·한계

통합은 새 설계 패턴보다 기존 계약이 함께 맞는지 확인하는 일이다. 본편에서 재검증하는 비용이 필요하다. 10~15분은 제출 기준이며 프로젝트의 최종 규모 상한이 아니다. 추가 구역과 기술 실험은 이 연결을 유지하면서 확장한다.
